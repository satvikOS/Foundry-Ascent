# @foundry/web — Foundry Ascent SPA

Vite 8 · React 19 · TypeScript (strict) · TanStack Router (file-based, auto code-splitting) · TanStack
Query · Tailwind CSS 4 (CSS-first tokens) · Radix (`radix-ui`) + CVA · lucide-react · cmdk · sonner ·
motion · react-hook-form + zod · react-markdown + remark-gfm.

The app is a static SPA served by CloudFront from `dist/`. It calls the API same-origin under
`/api/v1/*` (Vite proxies `/api` → `http://localhost:8787` in dev).

```bash
pnpm --filter @foundry/web dev         # http://localhost:5173 (needs the API on :8787)
pnpm --filter @foundry/web build       # also regenerates src/routeTree.gen.ts
pnpm --filter @foundry/web typecheck
pnpm --filter @foundry/web test        # Vitest + Testing Library (jsdom)
pnpm --filter @foundry/web e2e         # Playwright (see "End-to-end tests"; build first)
pnpm exec eslint apps/web --max-warnings 0   # from the repo root
```

`src/routeTree.gen.ts` is generated by the router plugin on `dev`/`build`. Commit it (typecheck needs
it); never edit it by hand.

## Data layer (`src/lib/api`)

**Always** go through the hooks or `api.*`; never call `fetch` directly for `/api/v1`.

- `client.ts` — `apiRequest` / `apiRequestOrEmpty` (204 → `null`) / `api.get|post|patch|delete` / `apiSend`:
  - `credentials: 'same-origin'`, JSON, `x-request-id` per request (server echo is preferred).
  - Every non-GET carries `x-requested-with: foundry-ascent` and `x-amz-content-sha256` = hex
    SHA-256 of the **exact bytes sent** (WebCrypto, pure-JS fallback in insecure contexts). A body-less
    POST/DELETE sends the empty-body hash and no body.
  - `Idempotency-Key`: mutation hooks generate one per call (`createIdempotencyKey()`) and the client
    reuses it across its own retries.
  - `503 database_resuming` is retried with exponential backoff (≈1, 2, 4, 8, 8… s, honours
    Retry-After) for up to 45 s. While waiting, the shared **"Waking up your workspace…"** banner shows
    elapsed time and a Cancel button (`resumingStore.cancelAll()`).
  - Responses are validated with the contract schema **in development** (`contract_mismatch` with
    paths only, never values) and trusted in production.
- `errors.ts` — `ApiError { status, code, title, detail, requestId, retryAfter, fieldErrors }` mapped
  from RFC 9457 problem+json (non-JSON bodies map from the status; their content is never shown).
  `errorMessage(error)` gives plain-language copy for every code. Aborts stay `AbortError`.
- `sse.ts` — SSE over POST for turns: `streamTurn(sessionId, body, { signal, idempotencyKey })` is an
  async generator of `TurnStreamEvent`s (validated with the shared contract); `SseParser` handles chunk
  boundaries, CR/LF/CRLF, comments and multi-line `data:`.
- `query-keys.ts` — the only place keys are built. Keys are hierarchical:
  `queryKeys.venture.scope(id)` invalidates everything cached for a venture.
- `hooks/*.ts` — one file per §6 area. Each read exports `xxxQueryOptions()` (use it in route loaders)
  and `useXxx()`; each write is a `useMutation` hook that invalidates the right keys.

```tsx
import { useMemory, useMemoryAction } from '@/lib/api/hooks/memory';

const memory = useMemory(ventureId, { status: 'proposed' }); // data: MemoryObjectView[]
const act = useMemoryAction(ventureId);
act.mutate({ memoryId, action: { action: 'approve' } }, { onError: (e) => toast.error(errorMessage(e)) });
```

Route loaders prefetch with the new TanStack Query API (`fetchQuery`/`ensureQueryData` are deprecated):

```ts
loader: ({ context, params }) =>
  context.queryClient.query({ ...ventureOverviewQueryOptions(params.ventureId), staleTime: 'static' }),
```

### API contract (verified against `apps/api`)

Every hook parses the response with the schema `packages/contracts` pins for that endpoint (in
development; trusted in production builds), so drift fails loudly with `contract_mismatch`. Behaviour the
UI relies on beyond plain JSON bodies:

| Endpoint                                                                         | Response the web expects                                                                                     |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `POST /auth/sign-in`                                                             | 200 `SignInResponse` (= `Me`) plus the HttpOnly cookie; it seeds the `/me` cache (no second round trip)      |
| `POST /auth/sign-out`                                                            | 204, cookie cleared (also for an already-expired session)                                                    |
| `GET /health`                                                                    | `HealthResponse` (`version`, optional `db`); public, never queries the database, fetched at most every 5 min |
| `POST /ventures/:id/sessions`                                                    | 201 `CreateSessionResponse` (`SessionView`)                                                                  |
| `POST /sessions/:id/turns`                                                       | 200 `text/event-stream` — or problem+json when refused before acceptance (see below)                         |
| `POST /sessions/:id/end`                                                         | 200 `{ session, recap }` (`recap` null for ephemeral sessions)                                               |
| `POST /ventures/:id/memory`                                                      | 201 `MemoryObjectView`                                                                                       |
| `PATCH /memory/:id`                                                              | 200 `MemoryObjectView` (`correct` returns the NEW version); **`delete` → 204, no body** (resolved as `null`) |
| `POST /ventures/:id/documents`                                                   | 201 `{ document, upload }` (presigned PUT, 5 min, signs content-type and content-length)                     |
| `POST /documents/:id/complete`                                                   | **202** `DocumentView` while ingestion runs (`processing`), 200 when already settled; the list polls         |
| `DELETE /documents/:id`                                                          | 204                                                                                                          |
| `POST /ventures/:id/escalations`, `PATCH /escalations/:id`                       | 201 / 200 `EscalationView`                                                                                   |
| `POST /personas/:id/releases`, `POST /persona-releases/:id/approve`              | 201 / 200 `PersonaReleaseView`                                                                               |
| `GET /persona-releases/:id`                                                      | `PersonaReleaseDetailResponse`: the full draft the studio reviews before approval (403 for other EIRs)       |
| `GET /sessions/:id`                                                              | `SessionDetailResponse`; blocked turns carry `blocked` (`reason`, `supportMessage`, `escalationId`)          |
| `POST /personas/:id/suspend` · `resume`                                          | 200 `PersonaView`                                                                                            |
| `POST /eir/reviews/:turnId`                                                      | 201 `{ reviewId, turnId }`                                                                                   |
| `POST /program/ventures`                                                         | 201 `ProgramVentureRow`                                                                                      |
| `POST` / `PATCH /program/resources[/:id]`                                        | 201 / 200 `ResourceView`; PATCH sends only changed fields (`UpdateResourceRequest`, incl. `status`)          |
| `GET /program/escalations`                                                       | `EscalationQueueResponse` (metadata only, never the packet)                                                  |
| `GET /program/assignees`                                                         | `EscalationAssigneeListResponse`: the tenant's EIRs and program leads, the routing dialog's only choices     |
| `POST /program/escalations/:id/route`                                            | 200 `EscalationQueueItem` (status `routed`); only from `awaiting_assignment` / `routed` / `acknowledged`     |
| `POST /admin/principals`                                                         | 201 `AdminPrincipalRow` (the dialog offers "Issue access code" for `row.principal.id`)                       |
| `POST /admin/principals/:id/access-codes`, `POST /ventures/:id/team/invitations` | 201 `AccessCodeIssued`; one-time secret, a replayed key gets 409 (never cached or logged)                    |
| `DELETE /admin/access-codes/:id`                                                 | 200 `{ accessCodeId, revokedAt }`                                                                            |
| `POST /turns/:id/feedback`                                                       | 201 `{ feedbackId }` (body not used)                                                                         |

**Turn stream.** Frames are `event: <name>` + one JSON `data:` line holding the full `TurnStreamEvent`
(the JSON carries `event` too; the two must agree), with `: keep-alive` comments every 15 s:
`turn.accepted` → `turn.status` × n → `turn.completed` | `turn.blocked` | `turn.error`. A refusal before
acceptance (404/409/422/423/429/503) is a plain problem+json response and surfaces before any event.
Every `turn.error` carries the `requestId` (shown for support); `retryAfterSeconds` holds "Try again"
until it has passed. A replay that finds the original turn still being answered (`conflict` with
`retryAfterSeconds`) is replayed automatically with the same key after the wait, up to
`MAX_PENDING_REPLAYS` times ("Still answering · checking again in 5 s").

**Blocked turns.** The live `turn.blocked` event and, after a reload, `TurnView.blocked` carry the same
`reason`, `supportMessage` (crisis lines and university support, rendered as safe Markdown) and the
drafted `escalationId`; `BlockedPanel` renders either, so a reloaded crisis-blocked session still shows the
humane support message.

**Idempotency.** Every write sends an `Idempotency-Key` (one per user intent; the client reuses it across
its own `database_resuming` retries). For turns the key is bound to the accepted turn: when an attempt
ends with an unknown outcome (network drop, interrupted stream, waking database, `409` still in flight),
sending the identical body again — "Try again" or the same text/mode/counterpart — **reuses the key**, so
the API replays the stored turn instead of running (and charging for) it twice. A turn the server
reported as failed (`turn.error`), a cancelled turn or a completed one starts fresh with a new key.

**Escalation status.** The UI shows the stored status (system design §6.2): `draft` / `awaiting_consent`
wait for the founder (`needsFounderConsent`), `awaiting_assignment` ("Waiting for assignment") is consented
and waits in the program team's routing queue, `routed` / `acknowledged` have an assignee. The program
queue offers "Route" only for routable states (`isRoutable`) and picks the assignee from
`GET /program/assignees` (never a typed id).

**Errors.** problem+json → `ApiError` (`code`, `requestId` from the body or `x-request-id`, `retryAfter`
from `retryAfterSeconds` or `Retry-After`). `database_resuming` (503) is waited out with the "Waking up
your workspace…" banner; `locked_out` / `rate_limited` / `spend_cap_reached` (429) show when to retry.

## End-to-end tests (`e2e/`, Playwright)

The CI `e2e` job (`.github/workflows/ci.yml`) resets a pgvector Postgres with `pnpm db:reset`, builds the
SPA and runs `pnpm --filter @foundry/web e2e`. `playwright.config.ts` starts everything itself:

- the API dev server (`apps/api` `src/dev-server.ts`) on **:8787** with `DATABASE_URL`, `DB_DRIVER=pg` and
  `MODEL_PROVIDER=mock` from the environment (`SITE_ORIGIN` = the SPA origin; `CORE_TURN_RATE_LIMIT`
  raised so reruns against one database stay under the per-person turn limit);
- `vite preview` of the production build on **:4173**, which proxies `/api` to :8787.

| Variable                | Meaning                                             |
| ----------------------- | --------------------------------------------------- |
| `E2E_BASE_URL`          | SPA origin (default `http://localhost:4173`)        |
| `E2E_API_URL`           | API origin (default `http://localhost:8787`)        |
| `E2E_OWNER_ACCESS_CODE` | owner code printed by `pnpm db:reset` (required)    |
| `DATABASE_URL`          | the database `db:reset` created (passed to the API) |

Projects: `setup` (signs in the owner, issues the seeded founder a code through the admin API, saves both
browser states under `node_modules/.cache/foundry-e2e-auth`), `desktop` (1440 × 900: the founder journey,
document upload and axe checks) and `mobile` (390 × 844 smoke). One worker, because everything shares one seeded database.

- **Journey** — landing → owner sign-in → admin issues an access code to the seeded founder (Maya
  Okafor-Lindqvist, QuietQuad) → sign out → founder sign-in → overview → diagnose session → message with
  live progress steps (the download is throttled through DevTools so the steps are observable) → cited,
  structured answer → evidence inspector → approve the proposed memory → end session → recap → memory
  page shows the approved item → a high-risk (IP) question is escalated and the founder approves sharing.
- **Documents** — upload a Markdown file (presigned PUT to the dev server's local S3 stand-in through the
  preview proxy) → `complete` (202 while processing) → the list polls until it is Ready → delete.
- **Accessibility** — `@axe-core/playwright` with WCAG 2.0/2.1/2.2 A + AA tags on landing, sign-in,
  overview, session (with an answer), memory and admin principals, in dark **and** light themes: zero
  serious or critical violations.
- **Mobile** — landing, sign-in and the session page: no horizontal scroll, no text clipped at the right
  edge, primary controls inside the viewport with ≥ 24 px targets.

Run locally against a scratch database (never the shared `foundry` one):

```bash
LOCAL_DB_NAME=e2e_local pnpm db:reset          # prints DATABASE_URL and a DEV owner code (local only)
export DATABASE_URL='postgresql://fa_master:fa_master@localhost/e2e_local?host=/var/tmp&port=54329'
export E2E_OWNER_ACCESS_CODE='…'                 # from the reset output; never commit or paste it
pnpm --filter @foundry/web build && pnpm --filter @foundry/web e2e
```

Locally the config uses the Playwright Chromium that matches the installed release, or — when only an
older build exists under `PLAYWRIGHT_BROWSERS_PATH` (e.g. `/opt/pw-browsers`) — the newest one found there.
Reports: `playwright-report/` (HTML) and `test-results/` (failure screenshots; traces only outside CI).
Access codes are typed with `fillSecret()` so they never appear in step titles or the uploaded report.

## Auth and roles

- Guards run in `beforeLoad`: `requireMe(context, location)` redirects to
  `/sign-in?redirect=…` (same-origin paths only, `safeRedirectPath`). `$tenant/app` also redirects a
  wrong tenant slug to the principal's tenant and puts `me` on the route context.
- Console layouts throw `ForbiddenError` → the default error component renders "No access".
- `lib/auth/roles.ts`: `hasRole`, `hasAnyRole`, `isMember(me, ventureId, roles?)`, `canWrite`
  (founder/team), `isFounder`, `isAssignedEir`, `canAccessVenture`, `canUseEirStudio`,
  `canUseProgramConsole`, `canUseAdminConsole`. These decide what to **show**; the API is the authority.
- In authenticated pages use `useRequiredMe()`.
- Any `401 unauthenticated` clears cached data and sends the person to sign in.

## Design system

Tokens live in `src/styles/globals.css`, each declared once as `light-dark(<light>, <dark>)`:
dark-first (`#0B0B0B` canvas, `#151515` raised, `#303030` border, `#F4F4F2` text, `#A6A6A3`
secondary, `#FFFFFF` focus) with a matching light theme. Use the semantic Tailwind colours
(`bg-background`, `bg-card`, `text-muted-foreground`, `border-border`, `text-success`, `bg-warning/10`,
`bg-sidebar`…), never raw hex. Theme: `useTheme()` / `setTheme('system'|'dark'|'light')` (persisted,
works before JS via `color-scheme`).

Rules:

- **Status = icon + label + shape, never colour alone.** Use `StatusBadge` for every status.
- Numbers in metrics/tables: add `tabular`.
- Every interactive element needs a visible focus style (the defaults handle it) and an accessible
  name; icon-only buttons need `aria-label`; decorative icons `aria-hidden`.
- Motion is decorative only and disabled under `prefers-reduced-motion` (global CSS + `motion-safe:`).
- No inline `<style>`/`style=""` strings or `data:` URIs (strict CSP). React `style={{…}}` props are
  fine (applied through the CSSOM).
- Never log or `announce()` prompts, answers, memory or document content.

`<Markdown>{answer}</Markdown>` renders Markdown + GFM only (raw HTML skipped, images never loaded,

with the route's `head`:

```tsx
export const Route = createFileRoute('/$tenant/app/ventures/$ventureId/memory')({
  head: () => ({ meta: [{ title: 'Memory' }] }),
  component: MemoryPage,
});

function MemoryPage() {
  return (
    <PageContainer size="wide">
      <PageHeader title="Memory" description="…" actions={<Button>Add memory</Button>} />
      <SectionCard title="Proposed" icon={Brain}>
        …
      </SectionCard>
    </PageContainer>
  );
}
```

Loading → skeletons inside `aria-busy` regions; empty → `EmptyState`; failure → `ErrorState`
(`onRetry={() => query.refetch()}`; shows the copyable request ID).


Only one `<Inspector>` should be mounted per page. Section pages get the venture via
`useVenture(ventureId)` (already cached by the layout loader).

### DisclosureBanner (required)

Every session view and every export must show the synthetic-identity disclosure:

```tsx
<DisclosureBanner text={session.disclosure} />              // full-width strip (session views)
<DisclosureBanner variant="inline" />                        // callout inside a card
<DisclosureBanner variant="print" text={session.disclosure} /> // exports / print views
```

Text precedence: `text` prop → `Me.disclosure` → `DEFAULT_DISCLOSURE`. It is not dismissible.

## Security notes

- CSP compatibility: the build emits no inline scripts and no `data:` URIs; sonner's runtime
  `<style>` injection is removed at build time (its CSS ships in our stylesheet). Radix's modal
  scroll-lock still attempts to inject a `<style>`; under `style-src 'self'` it is blocked harmlessly
  (an equivalent rule is in `globals.css`).
- Uploads go directly to S3 with the presigned URL (no cookies, no CSRF/SHA headers).
- `localStorage` holds UI preferences and a "probably signed in" hint only — never tokens or content.
