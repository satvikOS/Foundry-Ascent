# Presentation boundary and HeyGen replacement

Access/verification date: 2026-11-03. The local character is implemented. The amended remote adapter is contract-tested, **not live-validated on this branch**.

## Ownership

Foundry owns identities, consent, coaching prompts, retrieval, memory, session records, STT, TTS, turn completion, cancellation and evaluations. Presentation providers draw a character or video. No Foundry reasoning or student transcript is delegated to a local renderer.

`apps/web/src/lib/realtime/avatar.ts` is the existing provider-neutral lifecycle. `presentation.ts` negotiates audio ownership, amplitude/provider synchronization, remoteness, interruption and lack of visemes. `mount`/`unmount` attach and release the surface; `setState`, `setLevels` and `speak` communicate real state, outgoing audio level and validated speech boundaries. Optional `connect`, `onLost`, `video`, `media`, `renderer` support remote providers without requiring them of the local character. `FaceRenderer` accepts validated units and provides interrupt/close. Server `EmbodimentProvider` owns vendor session start, audio relay, interruption, keepalive and stop. UI readiness/loss comes through the existing call-face controller. Provider codecs, tokens and transport objects stay in these adapters.

## Free provider

`character.ts` and `character.css` contain original inline SVG artwork and restrained breathing/blinking. It is a surrogate character, not an EIR's likeness. Mouth opening follows actual outgoing analyser RMS, with a silence threshold and immediate closure. It is amplitude animation, **not phoneme-level lip sync**. The renderer neither requests a microphone nor synthesizes speech. No additional dependency, download, expiring credits, metered avatar API or server inference is required. Existing Bedrock, Transcribe, Polly, hosting and transport still cost money.

The character is lazy-loaded when selected. Animation runs outside React updates. Reduced motion disables optional motion; backgrounding cancels sampling and closes the mouth. Switching to the sphere preserves the same engine and session. A failed character chunk falls back to the sphere; a failed remote provider uses local presentation. Native browser speech fallback cannot expose its outgoing waveform through Web Audio, so this character does not pretend to lip-sync that path. Production Polly/Web Audio and the tested WAV fixtures do provide levels.

## Exact future activation steps

The repository already contains a HeyGen integration; a new SDK or conversational rewrite is unnecessary.

1. Review and merge the branch through the repository’s required PR/code-owner review process. Merging `main` deploys production, so follow the existing release review. Do not put real keys in local `.env` files.
2. Set/rotate repository Actions secret `HEYGEN_LIVEAVATAR_API`. The user reports it already exists; existence was verified by name, not by reading its value. Run the existing **Ops - sync HeyGen key** workflow on `main` to write `foundry-ascent/media/heygen` in AWS Secrets Manager. The API reads the key server-side. No key enters the browser.
3. In `infra/cdk/config/production.json`, select `media.face.provider: heygen-liveavatar`, `media.face.mode: lite`, the appropriate audience and current configured limits. Keep `media.voice` and the Foundry speech configuration unchanged. Use the existing infrastructure schema and `docs/runbooks/avatars.md` for the exact settings; `MEDIA_FACE_MODE=lite` is the local-development equivalent. Never select FULL merely to enable a face: FULL delegates voice and changes this ownership contract.
4. Select a valid LiveAvatar avatar ID on the vEIR's consented `avatarRef`, recording active likeness/embodiment consent through the existing studio workflow. Do not enter a voice ID for LITE. Consent withdrawal remains authoritative. Configure the existing allowed LiveKit/vendor CSP origins through infrastructure. No wildcard CSP or browser API key is needed.
5. Activate the existing `heygen-liveavatar` adapter in runtime configuration. It uses REST `/v1/sessions/token` (LITE), `/start`, `/keep-alive`, `/stop`; the server holds returned `ws_url`, waits for `session.state_updated: connected`, relays PCM16 mono 24kHz in ~1s chunks and closes each command socket after typed acknowledgments. The browser uses installed `livekit-client` **2.22.4** for the returned room/token. No new vendor SDK is installed. All chunks and the commit share the first chunk's utterance ID. Duplicate server event IDs count once. `agent.interrupt` waits for `agent.audio_buffer_cleared` under its own command ID.
6. Run `pnpm --filter @foundry/api exec vitest run src/adapters/heygen-liveavatar.test.ts`, browser face/lifecycle regressions, and the existing **Ops - conversation lab**, `suite=face`, `face_mode=lite`, within a reviewed budget. The credential-bearing environment permits `main` only today. Also rerun `suite=voice` to compare Polly-only against LITE.
7. With the real provider, verify first connected frame, exactly-once audio, chunk/utterance correlation, interruption at startup/mid-sentence, socket loss, max-duration and idle stop, reconnect during cancellation, approved state retention, cost accounting and secret redaction. Measure first useful audio and the absolute caption/mouth/audio offset over prolonged sessions. Record browser, region, versions, n and p50/p95/p99. Reject accumulating drift. A shared adapter contract does not imply equal visual quality or zero additional remote latency.

## Cancellation and fallback

A student interrupt stops the local player synchronously, aborts turn/queued speech fetches, increments cancellation generations and reports only units actually heard. Delayed decoded buffers and stale stream units are ignored. Remote rendering is interrupted and muted through its single media element while the server clears its buffer. On remote failure, subsequent speech uses the local engine; the local character never waits for a remote video frame. Captions and the session record stay attached to the same conversation. Ending releases tracks, worklets, audio nodes, connections, callbacks and presentation surfaces.
