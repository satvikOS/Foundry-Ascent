# Foundry Ascent upgrade — review and evidence

Working upgrade: [PR #35](https://github.com/satvikOS/Foundry-Ascent/pull/35), branch `codex/ascent-product-upgrade`. Implementation commit `d22b05f`, with subsequent strict-lint and token-use fixes. Production remains at `04df967`, verified through the public health endpoint on 2026-11-03. This is a reviewable application upgrade, **not a claim that every requested acceptance goal is complete**.

## Implemented

- Restored explicit approval for typed AI venture memory. Turn/recap/distillation candidates remain pending; retrieval excludes unapproved AI items. Existing unapproved active items return to review. Approval preserves the distinction between student-reported and verified information.
- Rejection, correction and deletion withdraw generated digests, source-derived notebook lines and opener copies. Source-session distillation is fenced against restoring withdrawn context. The transcript stays available for review. This deliberately reduces automatic recall from an affected conversation; corrected approved memory remains usable.
- Added distinct, self-approved student profiles and learning reflections, scoped by tenant, venture and principal. Profile updates detect stale versions. Settings provide inspection, correction, clearing, reflection deletion and JSON export.
- Added a compact editable context disclosure. It fetches only when opened, with bounded parallel requests for three approved items and a pending-review check. The conversation remains the main surface.
- Strengthened the versioned coaching policy around diagnosis, the four intake outcomes, evidence calibration, demonstrated competence, realistic constraints, direct answers, corrections and natural endings. No intermediate evidence-ladder rungs were invented. The briefing supplies only assertion and retained behavior as endpoints.
- Added an original free live character, lazy-loaded alongside the sphere. Its mouth follows actual outgoing Web Audio amplitude; silence/cancellation closes it. No phoneme-level lip sync, real-person likeness, webcam tracking, trial credits or avatar API is used. Normal speech ownership remains independent.
- Reused the existing provider-neutral avatar lifecycle and added capability negotiation. Corrected LiveAvatar LITE acknowledgment correlation/counting and duplicate-event handling against current official documentation. Provider settings and credentials do not enter coaching components.
- Bounded voice diagnostic samples, stopped hidden presentation sampling, removed captions-only/fake waveform speaking cues, and released completed playback buffer sources. Preserved existing streaming, cancellation, echo/backchannel handling, text alternatives and permission recovery.
- Retained the existing OLED/off-white system, self-hosted typography and minimal shell; added shared presentation/motion/touch tokens. No new runtime dependency or service was added.

## Measurements

Hardware/browser/versions and network conditions: `evidence/environment.json`. Local measurements use Apple M4 Max, arm64, macOS 26.6.2, Node 24.21.0 and Chromium 156.0.8078.4. Page tests throttle 40ms RTT, 20Mbit/s down, 5Mbit/s up; phone CPU is a 4× slowdown, not a real phone. Cold application loads and warm navigation are separate. Repeat results, percentiles, sample counts and network waterfalls are retained in `evidence/performance.json`. Final cold-load LCP p50/p95/p99 was 640/640/640ms on the laptop profile and 880/880/880ms with 4× CPU slowdown; n=5 each. CLS was ~0.0031. Composer readiness p50 was 639ms / 892ms, compared with initial single samples of 631ms / 881ms. These results show a small measured loading cost while staying within the lab budgets, not a speedup. Warm New chat navigation p50 was 12ms / 52ms. Field INP is not measured.

Local graph-stop results must not be substituted for that work.

Some critical checks were “not measured.” LITE turn-to-level-onset p50/p95 was 2,419/3,149ms (n=2), versus Polly-only 1,741/3,172ms (n=2); these tiny, mixed-stage samples cannot prove remote synchronization or a causal penalty. The existing Actions lab provides a live-model simulator/judge route; this new corpus still needs integration into its live behavioral runner, scoring and human calibration.

## Blocked

AWS and HeyGen secrets exist in GitHub Actions. Their values were not copied out or placed in local files. The credential-bearing `conversation-lab` environment currently allows `main` only; the repository's protected-main review process also deploys production on merge. The upgraded review branch therefore cannot use that environment under the current approved policy. No policy was weakened or approval gate bypassed. A reviewed release/merge is the precise dependency for upgraded live-provider validation. The public production health check and main-branch baseline verify the existing deployment, not deployment of these changes.

Client ratification is still needed for the six-rung ladder's four intermediate definitions. The application describes actual evidence and uncertainty instead of presenting invented rung names as approved requirements.

## Failure history retained

The initial browser upgrade run passed 108/121 with 13 failures; the next passed 120/121 with one failure. They exposed changed approval/presentation expectations, a strict text selector in the new journey, and stale confirmed-memory queries in tests. They are retained as `iteration-browser*.json`. The final acceptance file reports the repaired run separately.

The initial media run passed 40/160 and failed 120 because the fixture passed unbound browser timer functions (Illegal invocation). Across the failed run, corrected run, 11-case probe and two repeats, 651 media-case executions produced 531 passes and 120 initial harness failures. These repetitions are not additional distinct cases; `media/run-history.json` retains each summary. A first soak was interrupted by Vite reloading during concurrent source edits; its error is retained and the completed run used an isolated harness page with the actual shared CSS loaded. Two completed five-minute runs were performed; the artifact reports the final one. Tests also caught and repaired migration replay assumptions, an actual DST elapsed-time bug in the lab helper, discarded-source summary restoration, and student input normalization. A final CI run also exposed one intermittent continuity failure and two CodeQL findings in the screenshot viewer. A deterministic red regression reproduced the continuity defect: the generated word “whether” falsely added topic overlap between library pricing and pilot locations. The matcher now treats it as framing, and the regression explicitly establishes that earlier thread. The viewer now uses a fixed image catalog; all 28 pairs / 56 images loaded after the repair. Details are retained in `evidence/ci-repair.json`. The full conversation protocol corpus is being rerun on the amended source. GitHub CI also caught two strict-lint violations in new code; both were fixed without changing behavior and lint was rerun. Under heavy concurrent local load, two existing timing-ratio unit tests failed; the full serial AI acceptance run passed all 1,772 without weakening their bounds.

Students can now inspect and approve what becomes venture memory, correct context without stale summaries returning, keep personal learning records separately, and select a lightweight live character without changing their conversation or voice. The measured browser/media results support local responsiveness; live mentoring quality and full voice latency still require the release-bound validation above.
